## 3. Deliberately not implemented

Trust-anchor distribution, anchor-signed bundles, durable monotonic history
(**O8**); any timestamp authority or default root (**O9**) — only a
caller-pinned `TimestampVerifier` interface; `high-assurance` historical
acceptance; shared replay infrastructure; the reserve/perform/commit protocol;
Encompute integration. `TrustHistory.authenticated` is an unset seam: nothing in
the library can produce an authenticated history, so historical acceptance of
retired/compromised keys is **refused by default**.

## 5. Canonical vectors

`tests/vectors/report_v2/vectors.json`, generated by `generate.py` from a
**test-only** Ed25519 key derived from a public constant
(`sha256(b"regaudit-fhe/test-vector/ed25519-seed/1")`; never trust it).

* Key fingerprint: `f5a124b4ff5b3253aa23c917d460cfaed57cec28ecc4b7a43d72785828aa2256`
* `full` — signing-input sha256 `2dccddae8e96f35d15da3665ded1aed685d6e3db64c3051c889011be7dc4741b`,
  sealed digest `fcadd05ebbc4f1db772f713b25e148457766363b9094851fe9e954c5572d3a69`
* `minimal` — signing-input sha256 `26af001ffb0d9b3b361710c8ee7c15b79a80e4999dc1d49597875ac2974e3470`,
  sealed digest `6b59597b1f62714012afbe4d6c81e6a8345170189209f04810ab2094acc38f44`
* Domains: signing `regaudit-fhe/report/v2/sign\0`, sealed digest
  `regaudit-fhe/sealed-envelope/v2\0`.
* **17 parse refusals:** duplicate top-level and nested keys, `NaN`, overflowing
  float, BOM, invalid UTF-8, lone-surrogate escape, excessive nesting, unknown
  top-level field, key identity inside the receipt, missing `key_id`, uppercase
  UUID, naive `issued_at`, empty audience, unknown schema, non-canonical
  signature base64, truncated envelope.
* **10 verify refusals:** tampered result, tampered audience, swapped `key_id`,
  signature without domain separation, signature by a different key, wrong signed
  fingerprint, wrong signed issuer, deployment outside scope, v2 relabelled as v1,
  timestamp token over a different artifact.
* The golden values are **duplicated in `tests/test_report_v2_vectors.py`**, so
  regenerating the vector file alone cannot hide a format change.
* Float formatting is Python's `repr`; a non-Python verifier needs RFC 8785
  (or byte-identical formatting) before claiming v2 compatibility. This is an
  open point, so **format stability is not claimed beyond these vectors.**

## 6. Breaking changes

Relative to the Phase 1 candidate and to released behaviour (full list in
`CHANGELOG.md`):

* `regaudit-fhe verify` exits 0 only when accepted. **Changed:** a consistent
  self-signed report exits `1` (was `0`); an unreadable/malformed `--trusted-keys`
  exits `3` (was `2`); no `--trusted-keys` and no `--allow-self-signed` is a usage
  error (`2`).
* `require_verified_timestamp` needs a `VERIFIED` timestamp (absent no longer
  passes) and a pinned verifier; v1 timestamps can never be `VERIFIED`.
* `ServerConfig.tsa_verifier` → `timestamp_verifier` (Phase 1 field, unreleased).
* `/v1/verify`: exactly `{"envelope": …}`, strict JSON, chunked bodies bounded,
  verification off the event loop. `server.PROFILES` moved to `verification`;
  `server.VerifyRequest` removed.
* Non-development profiles are enforced at `build_app()`/startup (trust store,
  `max_age`, persistent replay cache, replay mode; `verifier_id` for
  `high-assurance`).
* `report.v1` is refused under `confidential`/`high-assurance` (no
  `audit_run_id`, so it cannot be replay-checked) — see §10.
* `TrustStore`: one key per `key_id`, Ed25519 only, immutable, consistency-checked.
* `valid` deprecated on both result types (`DeprecationWarning`), still present.

## 10. Unresolved specification ambiguities (owner decisions requested)

1. **Consumption label.** I report `RECORDED_LOCAL`, not `CONSUMED`, because recording
   at verification is not "after the operation completed". Add it to §6.2 or reserve
   `CONSUMED` for reserve/perform/commit.
2. **`report.v1` under `confidential`.** §6 mandates replay checking, §7 says v1 is
   "allowed, labelled". They conflict for v1 (no `audit_run_id`); I refuse v1 there.
3. **CLI with no trust material.** Exit `2` (usage) rather than `3`; your table lists
   `--strict` without trust material under `2`, which I generalised.
4. **`require_verified_timestamp` with an absent timestamp** now fails (Phase 1 let it
   pass). Confirm this stricter meaning.
5. **Unix sockets under uvicorn** report no server address and are refused; the spec
   allowed them. Confirm fail-closed is acceptable or define how to detect them.
6. **Accuracy handling.** I use `genTime + accuracy` as the latest possible signing time
   (strict `<` for compromise, `<=` for retirement). Confirm.

## 11. Remaining limitations

* No authenticated trust history: historical acceptance is refused unless a caller
  injects one (O8). `high-assurance` never accepts historical keys.
* No timestamp authority or default roots (O9); no production `TimestampVerifier`.
* Replay detection is local only. `RECORDED_LOCAL` is not coupled to any operation and
  is not crash-safe exactly-once; independent verifiers can each accept a report once.
* `report.v2` is produced through the library API only. `regaudit-fhe audit` and
  `/v1/audit/*` still emit `report.v1` signed by an ephemeral key.
* A header-less local reverse proxy is indistinguishable from a direct local client.
* `BodySizeLimitMiddleware` still checks `Content-Length` only for the other endpoints
  (pre-existing; only `/v1/verify` bounds chunked uploads).
* Number formatting is Python's `repr` (RFC 8785 is the open point).
* `AuditEnvelopeV2` is a mutable dataclass (copy it before sharing).
* Python 3.10 and the real CI matrix were not run.

## 12. Release gates still open

Phase 3A establishes a candidate trust core only. The larger confidential-computation
limitations from RA-01 are untouched and independent of this work: no demonstrated
separation between the evaluator and the decryption-key holder, incomplete OpenFHE
behavioural verification, and incomplete differential-privacy enforcement. O8 and O9
remain unresolved and were not decided or simulated. A public push, PR, merge or
release remains on HOLD pending separate approval.
